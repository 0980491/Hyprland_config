# Desktop — Hyprland 0.55 (Lua) + Quickshell

## Where everything lives

```
~/.config/hypr/
  hyprland.lua          entry point; only require()s conf/*
  conf/env.lua          environment variables
  conf/monitors.lua     outputs (10-bit, VRR while fullscreen)
  conf/look.lua         gaps, borders, blur, glow, animations, misc
  conf/input.lua        keyboard (us + altgr-intl), mouse, gestures
  conf/workspaces.lua   workspaces pinned per monitor + smart gaps
  conf/rules.lua        window and layer rules
  conf/binds.lua        keybinds (all described → SUPER+/ lists them)
  conf/autostart.lua    what starts with the session + event automation
  conf/colors.lua       GENERATED by matugen (don't edit)
  conf/vars.lua         shared paths and programs
  hyprlock.conf         lock screen
  hypridle.conf         idle: lock at 8 min, screens off at 12
  colors.conf           GENERATED by matugen, only hyprlock uses it
  scripts/              wallpaper, screenshots, game mode, night light…
  legacy/               superseded files, kept just in case
  hyprland.conf.old     the old hyprlang config, for reference

~/.config/quickshell/   bar, notifications and OSD (QML)
~/.config/rofi/         config, themes and scripts/ for the menus
~/.config/matugen/      templates that generate every colour
```

`hyprland.lua` wins over `hyprland.conf`. The `.conf` stays as a safety net: if
you delete or break the `.lua`, the session still starts.

Every SUPER bind is mirrored on **SUPER+ALT**, for when you play over
Sunshine/Moonlight and the client swallows the SUPER key.

**SUPER + /** opens the full cheat sheet, read from `hyprctl binds`.

| `SUPER N` | Wi-Fi · `SUPER SHIFT B` Bluetooth |

| `SUPER S` | region screenshot · `SUPER SHIFT S` screenshot and annotate |

got pressed by accident often enough to be worth removing; logging out is in the
power menu (`SUPER ESC`) behind a confirmation.

## Wallpapers

```bash
~/.config/hypr/scripts/wallpaper.sh image <path> [monitor]
~/.config/hypr/scripts/wallpaper.sh we <id> [monitor]      # workshop id
~/.config/hypr/scripts/wallpaper.sh random [monitor]
~/.config/hypr/scripts/wallpaper.sh restore                # used by autostart
~/.config/hypr/scripts/wallpaper.sh theme                  # only regenerate colours
~/.config/hypr/scripts/wallpaper.sh off
~/.config/hypr/scripts/wallpaper.sh list-json              # catalogue for the picker
```

`SUPER B` opens the picker: a coverflow carousel in the shell
(`quickshell/WallpaperPicker.qml`), with images and Wallpaper Engine scenes in
the same strip. Type to filter, arrows **or the scroll wheel** move through it,
`Tab` picks whether it applies to one monitor or all of them, `Enter` applies.
The old rofi grid is still there on `SUPER SHIFT ALT B` in case the shell is not
running.

Changing the wallpaper makes matugen rewrite the palette and **everything**
recolours: Hyprland borders, the bar, rofi, kitty, hyprlock, btop, fastfetch,
KDE apps and the folder icons. The bar does it live because it watches
`colors.json`.

Two of those read their theme only at startup, so they change on the next run,
not on the spot:

* **btop** — the theme is written to `~/.config/btop/themes/matugen.theme` and
  `btop.conf` only points at it (`color_theme = "matugen"`). Careful: btop
  rewrites `btop.conf` from memory when it exits, so edit that file with btop
  closed. `main_bg` is left empty so kitty's transparency survives.
* **fastfetch** — colours and layout come from
  `matugen/templates/fastfetch.jsonc`; the icons are the `\uXXXX` escapes in
  that template. It replaced nitch, whose art was compiled into the binary, and
  the old binary is still in `/usr/local/bin/nitch`.

  **Terminals open to a bare prompt — nothing runs on startup.** `.bashrc`
  aliases `fastfetch` (and `nitch`, and `donut`) to `fastfetch/banner.sh`, which
  clears the screen and draws the info box with a tumbling torus beside it,
  turning until you press a key or Ctrl+C. `command fastfetch` still gets you
  the plain one-shot version.

  fastfetch cannot animate — it prints once and exits. So banner.sh composes the
  two halves itself: `fastfetch --logo none` for the box, the 200 frames in
  `fastfetch/donut/` for the torus, redrawing the block in place by walking the
  cursor back up.

  `FF_DONUT=0` falls back to a still `fastfetch/logo.txt`; so does anything odd
  about the terminal (not a tty, `TERM=dumb`, or too small to fit the donut and
  the box side by side — a wrapped line would break the cursor arithmetic).
  `FF_DONUT_FPS` (default 15), `FF_DONUT_SECS` to make it stop by itself, and
  `FF_DONUT_CLEAR=0` to draw in place. The old Arch art is in
  `fastfetch/logo-arch.txt`.

  Three things the frames in `make-donut.py` get right, each of which looked
  broken when it was wrong:

  - **A whole number of turns over the frame count.** donut.c steps A by 0.04
    and B by 0.02 every frame. The first version used 32 frames for a full turn
    — 0.196 rad a step, five times coarser — and the tumble read as juddering.
    200 frames with A doing two turns and B one gives 0.063 rad and loops
    seamlessly.
  - **Constant frame height.** Trimming blank rows per frame made every frame a
    different height and the donut jumped up and down as it spun.
  - **Supersampling and a legible ramp.** One sample per cell speckles the
    shading at this size, so each cell is sampled 3×3 and averaged. The ramp is
    `.:-=+*#%@`: the classic `.,-~:;=!*#$@` has four glyphs that all read as
    "a small dot" in a terminal — and `$` is unusable anyway, because
    fastfetch's `file` logo type reads it as the start of a colour placeholder
    and it threw the info box 40 columns to the right. Keep `$` out of any logo
    file.

Folder icons follow the accent too. Papirus ships every folder in ~35 fixed
colours, so `matugen/apply-folders.sh` snaps the accent's hue to the nearest one
and builds `~/.local/share/icons/Papirus-Matugen`: a theme made only of symlinks
into `/usr/share/icons/Papirus-Dark`, which it inherits. Nothing is copied and
root is never needed — that is the difference from `papirus-folders`, which
rewrites `/usr/share` in place. The name ping-pongs with `Papirus-Matugen2` for
the same reason `apply-kde.sh` does it: GTK and KDE ignore a re-apply of the
name already active, and only the contents change.

Overriding `folder.svg` alone is **not** enough, and this is the trap: Papirus
points ~116 generic names per size at its blue icons, and several do not share
the target's name (`folder-camera` → `folder-blue-photo`, `desktop` →
`user-blue-desktop`). Worse, Dolphin does not ask for `folder` — it asks for
`inode-directory`, which Papirus links to `folder` → `folder-blue`. Those links
resolve *inside* Papirus-Dark, so inheriting it leaves them blue and the
override never gets consulted: GTK looked right while Dolphin stayed blue. So
the script follows every symlink to its end and re-points anything that lands on
a blue folder. If folders ever go blue again, that alias pass is what broke —
unless the accent itself is blue, in which case blue folders are correct.

To repaint apps that are already open, the script calls `/usr/lib/plasma-changeicons`,
the same binary System Settings runs. Writing `[Icons] Theme` into `kdeglobals`
by hand only takes effect the next time an app starts, which is why Dolphin used
to need a restart. GTK apps repaint from the `gsettings` write on their own.

Everything is themed from **one monitor** — the biggest one, DP-3 here (set
`WALL_MAIN=HDMI-A-1` to change it). Its wallpaper is what feeds the palette,
`current.png` for hyprlock, and the launcher image, so the secondary screen's
background never drags the colours around.

Wallpaper Engine's `--screenshot` is global: with a scene on more than one
monitor it writes the whole layout in a single image, so `wallpaper.sh` crops
the main monitor's rectangle out of it before anything else touches it.

The bar and the panels borrow the wallpaper's accent instead of staying the
same dark grey. `Config.qml` has the knobs: `barTint` (how much accent gets
mixed in), `barOpacity` (how much of the blurred wallpaper shows through) and
`panelTint`.

Wallpaper Engine runs as **one process** for every monitor, capped at 60 fps
(`WE_FPS=30 wallpaper.sh restore` to lower it), and pauses itself while a
fullscreen game has focus.

## Shell (Quickshell)

```bash
qs -d -n        # start (autostart does this)
qs kill         # stop
qs ipc call panel toggle calendar|notifications|volume|resources
qs ipc call panel dnd            # do not disturb
```

It reloads itself when any `.qml` is saved, and it is also the **notification
daemon**.

Bar layout: clock and system stats on the left, workspace dots dead centre, and
now playing plus the controls on the right. Panels open only on the monitor
whose bar you used, and they open on hover: move the pointer away and they
close, click to close one that is already open. Clicking inside a panel never
closes it, so sliders and lists work normally.

| Click on | Opens |
| --- | --- |
| clock | month calendar |
| gear | quick settings: toggles, volume, outputs, bluetooth devices |
| now playing | full player: cover art, progress, controls |
| CPU/RAM/GPU | per-core load, RAM and VRAM used/total, temperatures |
| network | quick settings (right click: the rofi Wi-Fi menu) |
| bell | notification centre (right click: do not disturb) |

The bar shows CPU %, RAM % and **GPU temperature**; the detail panel has the
rest. Scrolling works over the volume, the media widget and the workspace dots.

There is no system tray, no focused-window title and no peripheral battery
readout (all removed on purpose).
Apps that minimise to the tray keep running — reach them with `SUPER+TAB` or the
overview. To bring either back, move the file out of `unused/` and re-add it to
`qmldir` and `Bar.qml`.

The launcher (`SUPER+D` / `SUPER+Space`) has the search box and the current
wallpaper on the left with APPS / RUN / FILES / WINDOW buttons underneath, and
the results on the right. The image it uses is regenerated by `wallpaper.sh`
into `~/.cache/wallpaper/launcher.png`.

`~/.config/quickshell/Config.qml` holds the knobs you'll actually want to
change: which workspaces are pinned to each monitor, 12h vs 24h clock, network
speed readout, and whether toasts appear only on the focused monitor.

The overview cards show live thumbnails of the windows on each workspace,
captured with `ScreencopyView` pointed at `HyprlandToplevel.wayland` — Hyprland's
toplevel-export protocol can grab windows that are not currently on screen,
which is the only reason this works. They are single frames (`live: false`), not
streams: five workspaces of four windows would otherwise be twenty live captures
for a panel that is up for two seconds. The cards sit in one row while there are
six workspaces or fewer, because a 3-column grid left a hole where the sixth
card would have been.

The overview replaces the old `hyprexpo` plugin, which was dropped upstream and
never ported to the Lua era. If you'd rather have the native zooming one, the
closest maintained plugin is `hyprtasking`, but it only pins up to Hyprland
0.56.0 and you are on 0.56.2:

```bash
hyprpm update && hyprpm add https://github.com/raybbian/hyprtasking && hyprpm enable hyprtasking
```

## Audio

Crackling under GPU or CPU load (a heavy Wallpaper Engine scene, scrolling a
PDF) had two causes.

**PipeWire was not running in real time.** Every `data-loop.0` thread — the one
that has to hand a buffer to the sound card before the deadline — was on
`SCHED_OTHER`, so any burst of work could preempt it:

```bash
ps -L -o tid,comm,cls,rtprio -p $(pgrep -x pipewire)   # cls must be FF, not TS
```

rtkit-daemon runs, but nothing had granted the process the rlimits it needs
(`Max realtime priority` was 0 in `/proc/<pid>/limits`). The fix is the standard
one, and it needs a re-login to take effect:

```bash
sudo pacman -S realtime-privileges
sudo gpasswd -a "$USER" realtime
```

**The wallpaper was inside the audio graph.** `linux-wallpaperengine` runs muted
(`--silent`) but still creates a `Stream/Output/Audio` node, and WirePlumber
wired it straight to the speakers — putting a thread that waits on the GPU into
the graph the audio output is scheduled with. `pipewire/client.conf.d/` and
`client-rt.conf.d/50-wallpaperengine.conf` set `node.autoconnect = false` for
it, so the node exists but is never linked:

```bash
pw-link -l | grep -c wallpaper     # 0 = out of the graph
```

Two things that look like fixes and are not: `--no-audio-processing` does not
remove the node (it only turns off the analysis that makes scenes pulse to your
music), and a WirePlumber `stream.rules` entry runs too late — the link is
already made by then, which is why the rule lives on the PipeWire client side.

## If something breaks

- Config errors: `hyprctl configerrors`, and `hyprctl rollinglog | tail`
- Test changes safely: `Hyprland -c ~/.config/hypr/hyprland.lua` (nested)
- Run Lua against the live session: `hyprctl repl` or `hyprctl eval '<code>'`
- Go back to the old config: `mv hyprland.lua hyprland.lua.off`, then log out
- Backup of everything from before: `~/dotfiles/backup-*`
